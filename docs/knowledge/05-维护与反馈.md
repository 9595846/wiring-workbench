# 维护与反馈

## 设计、代码与发布各自维护

- 接线图保存为项目，修改前保留恢复点。
- OLED 保存设计后导出待审阅文件，再决定是否接入当前 Keil 工程。
- 继续维护同一份固件，保留芯片、库、编译器与工程结构，避免旧工程覆盖新修改。
- 每次记录修改文件、实现内容、实际执行的测试和仍未验证的事项。
- 发布版本固定来源提交，附校验值与验证摘要；不把本机用户目录直接压缩公开。

## MCP 的作用

MCP 是 AI 访问已保存设计的本地接口，不是 GitHub 上传工具，也不会自动烧录。接线端提供项目读取、原子编辑、静态检查、预览和恢复点等 12 个工具。网页未保存内容不可见；AI 更新后需要重新读取项目，旧修订号应拒绝覆盖。

先完成普通使用，再按 [MCP 配置说明](https://github.com/9595846/wiring-workbench/blob/main/MCP_GUIDE.md)连接。源码 MCP 与桌面套装默认数据位置不同，不能假定自动同步。

## 文档维护约定

本组笔记通过 Obsidian CLI 创建和读取。每篇保留 updated、tags、source_commit 等属性，并使用内部关联链接。公开到 GitHub 时只选择这组文档，将内部链接转换为相对 Markdown 链接，校验目标存在；不公开个人聊天、其他笔记、本机配置和密钥。

更新时先查看远端 HEAD 与现有笔记，检查同名文件和并发修改。应用程序源码、设计文件和文档快照分开核对。
